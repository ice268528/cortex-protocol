# E2E and Human Acceptance

本文件定义 Playwright E2E 的复用/沉淀规则和 Human Gate C。

## 1. E2E
当前 Work Item 存在适合自动化的用户可见流程时：
- 先检查现有 Playwright 覆盖；
- 已覆盖则复用；
- 预期行为变化则修改已有测试；
- 新增长期有回归价值的行为才新增测试。

不要为了满足流程强行创建没有长期价值的 E2E。

## 2. 测试沉淀
有长期回归价值的 Playwright 测试应提交到仓库，不作为一次性验收脚本丢弃。
优先验证用户可观察行为并复用项目已有 fixture/helper。

## 3. Human Gate C
实现、必要自动验证、review 和适用 E2E 完成后，停止并请求用户验收。

根据当前 change 提供必要信息，包括：
- 本次完成内容；
- 已完成的自动验证；
- 需要用户手动验证的场景；
- 操作方式和预期结果；
- 无法自动验证的内容（如有）。

只提供实际相关内容，不为完整模板编造场景。

## 4. 验收失败
用户验收发现问题后：
1. 修复；
2. 重跑受影响验证；
3. 必要时更新/新增 E2E；
4. 必要时重新 review；
5. 再次进入 Human Gate C。

人工验收期间和结束后的服务管理按 `runtime-and-services.md` 执行。
